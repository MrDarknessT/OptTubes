# Зерно · 96 оптических датчиков · Kotlin

Проект Android Studio на Kotlin, без сторонних библиотек интерфейса. Исходники приложения и тестов — `.kt`, сборочные файлы — Kotlin DSL `.gradle.kts`. Минимальная версия — Android 6 (API 23). Все надписи на русском. Работает без интернета; приложение не запрашивает разрешений.

## Запуск

1. Откройте эту папку через **Android Studio → Open**.
2. Выберите Gradle JDK 17 или новее (проверено на встроенном JDK 21), дождитесь Gradle Sync. Проект использует AGP 9.2.1, Gradle Wrapper 9.4.1 и SDK 36.
3. Если SDK установлен в другом месте, Android Studio создаст `local.properties` с вашим путём. Этот машинный файл в архив не включён.
4. Выберите Android-устройство или эмулятор и нажмите Run.
5. Выберите сценарий и нажмите **Начать уборку**. Кнопка **Скрыть настройки и описание** освобождает место для сетки. На телефоне панель прокручивается; в широком окне сетка содержит 12 столбцов вместо 8.

Архив проекта — `GrainMonitor-Kotlin-AndroidStudio.zip`. Готовая тестовая сборка — `GrainMonitor-Kotlin-debug.apk`, с отладочной подписью.

Kotlin встроен в AGP 9, поэтому отдельный `org.jetbrains.kotlin.android` не подключается. [Официальная документация Android](https://developer.android.com/build/migrate-to-built-in-kotlin).

Командная сборка: `gradlew.bat assembleDebug` в Windows или `./gradlew assembleDebug` в Linux/macOS. SDK и JDK должны быть установлены. При первом запуске Gradle может скачать зависимости.

Источник: `пример_отображения_датчиков_забивания.xlsx`, «Лист1», S75:U78. Массив-пример: E67:CV67, ровно 96 значений; сохранён в `app/src/main/assets/excel_example.json`.

| Код | Подпись в Excel | Интерпретация в симуляторе |
| --- | --- | --- |
| 0 | Пустой | Нет обнаруженного зерна |
| 1 | Идет сев | Есть поток; зелёный |
| 2 | Забит | Сигнал забивания |

Excel упоминает отправку строк до 20 мс и содержит примеры упаковки шестнадцатеричных данных. По запросу здесь моделируется уже **декодированный полный `int[96]` каждые 30 мс**. Аппаратный протокол и сборка полного кадра из строк не реализованы.

## Фильтрация

По умолчанию: окно **1800 мс**, экран **1500 мс**, режим **«Зелёный обнуляет окно»**.

**Каждые 30 мс создаётся новый полный `IntArray(96)`. Фильтр обрабатывает каждый пакет, независимо от частоты отрисовки.** Для каждой трубки хранится отдельная история за 1–2 секунды. При окне 1800 мс это около 60 исторических значений на трубку, а не 60 значений на все 96 трубок вместе.

Генератор работает в отдельном `ScheduledExecutorService` через `scheduleAtFixedRate(..., 30, MILLISECONDS)`. Время пакета фиксируется на потоке генератора, а не во время отрисовки. Обработка истории и интерфейса последовательна на главном потоке. Пакеты предыдущего опыта игнорируются после остановки или смены настроек.

Времена монотонные, на основе `SystemClock.elapsedRealtime()`. Окно определяется временем, а не фиксированным количеством пакетов. Android не является системой жёсткого реального времени: таймер может опоздать. При догоняющих вызовах с одинаковой миллисекундной меткой дубликат пропускается. Фильтр использует фактическое время пакета.

```text
Новый массив из 96 кодов каждые 30 мс
  → 96 независимых историй за 1–2 секунды
  → обработка на каждом пакете
  → сетка каждые 1 / 1,5 / 2 секунды
       ↳ переход в зелёный сразу
```

### 1. Зелёный обнуляет окно — основной режим

- `1` сразу устанавливает зелёный, удаляет историю и сбрасывает таймер плохого состояния.
- При следующем `0`, `2` или `3` начинается новое окно.
- Красный разрешён, когда с первого плохого пакета прошло полное окно и за это время не было ни одного `1`.
- До подтверждения сохраняется последний зелёный; при запуске без рабочего пакета показывается нейтральное `…`.
- При чередовании плохих кодов отображается самый частый плохой код в последнем окне. При равенстве выбран текущий входной код, если он входит в число лидеров, иначе первый лидер в порядке 0, 2, 3.
- Порог процентов отключён: история между зелёными содержит только плохие состояния, поэтому их доля всегда 100%.

### 2. Скользящее окно — эксперимент с долей плохих

- Значение `1` также немедленно устанавливает зелёный, но **не очищает историю**.
- Только после накопления полного окна `0/2/3` подтверждают красный, если суммарная доля плохих пакетов ≥ порога (по умолчанию 70%), либо плохие показания непрерывны целое окно.
- Код красного состояния выбирается по частоте среди 0/2/3.
- Следующий плохой пакет может снова подтвердить красный даже после рабочего пакета. Это намеренное отличие от основного режима.
- Доля считается по количеству пакетов. При регулярном периоде она соответствует доле времени; при неравномерной аппаратной передаче для точной доли времени понадобятся веса интервалов.

Нельзя одновременно обнулять историю при каждом зелёном и измерять в ней соотношение 70% плохих / 30% хороших. Два режима позволяют проверить обе политики без скрытого противоречия.

### Отрисовка и отсутствие данных

Подтверждённые тревоги, номера кодов, исходный массив и подробная статистика обновляются каждые 1 / 1,5 / 2 с. Переход панели в зелёный выполняется сразу при обработке рабочего пакета; это исключение из ограничения отрисовки. Новый красный появляется после фильтрации и ближайшего периодического обновления: при окне 1,8 с и экране 1,5 с задержка составляет примерно 1,8–3,3 с.

Если полных пакетов нет дольше окна (минимум 300 мс), выводится отдельный жёлтый статус `?` — «нет данных». Он не равен коду `3`. После перерыва история сбрасывается: отсутствие пакетов не засчитывается как непрерывное забивание. Старый массив во вкладке исходных показаний остаётся последним полученным массивом, его возраст виден в строке состояния.

**Окончить уборку** прекращает генерацию и очищает историю. При сворачивании приложения уборка также останавливается, чтобы не засчитывать время, когда симулятор не работал. Изменение сценария или параметров сбрасывает историю и время текущего опыта. Ручные воздействия сохраняются при смене настроек; новый старт и кнопка сброса удаляют их.

## Сценарии

1. Смешанный цикл 24 с: норма → забивание №13–16 → отключение №49–52 → пустые №81–96 → восстановление. Цикл повторяется.
2. Норма: рабочие импульсы длительностью 90 мс через 300–900 мс, между ними пусто; основной фильтр остаётся зелёным. Импульс шире одного пакета, чтобы небольшое опоздание Android-планировщика не пропускало его целиком.
3. Короткие ложные сигналы 2/3 по 300 мс.
4. Постоянно забиты №13–16.
5. Постоянно отключены №49–52.
6. Все пустые: подтверждение кода 0 после окна.
7. №1–12 забиты 5 с, затем работают 5 с; цикл 10 с.
8. 70% кода 2 / 30% кода 1: сравнение двух режимов.
9. Независимый случайный код 0–3 в каждой трубке, фиксированный seed 96 для повторяемости. Это стресс-тест, а не физическая модель потока.
10. Постоянный полный массив из строки 67 Excel.
11. Потеря пакетов: в каждом цикле 12 с пакеты отсутствуют с 4 до 8 с.
12. Все 96 трубок действительно забиты: постоянный код 2; после подтверждения вся сетка красная.
13. Очень редкий поток: рабочий импульс раз в 1,65 с. При окне 1 с возможны красные между зёрнами, а при 1,8–2 с основной режим сохраняет зелёный. Это демонстрация выбора окна по реальному интервалу между зёрнами.

У каждого сценария в приложении есть описание: что генерируется, что ожидается на панели и почему. Общий случайный режим — стресс-тест: частые случайные 1 могут предотвращать непрерывную тревогу в основном режиме, и это ожидаемо. Код 0 означает отсутствие обнаруженного зерна и сам по себе не доказывает механическое забивание.

Нажмите любую трубку для фиксации 0/1/2/3, возврата в авто или подачи одного пакета 1. Один зелёный пакет особенно полезен для проверки сброса окна. При сценарии потери пакетов ручной пакет также ожидает возобновления передачи.

**Показать исходные показания** открывает исходную сетку и полный массив. Дополнительный флажок включает мерцание исходной сетки каждые 30 мс; сглаженная панель продолжает работать по своей политике. Детали выбранной трубки содержат вход, отображаемый статус, количество исторических пакетов, долю плохих и время с начала плохой последовательности. Строка **Почему** поясняет накопление, удержание зелёного, восстановление, непрерывную проблему, процентный порог или отсутствие пакетов. Журнал хранит последние 12 изменений панели.

## Подключение реального массива

`SensorFilter.kt` не зависит от Android. Вызовите `accept(values: IntArray, nowMs: Long)` для каждого полного кадра на одном последовательном потоке, затем `checkStale(nowMs)` и `statuses()`. Диагностический снимок получается через `diagnosis(index, nowMs)`. Время должно строго возрастать и использовать одни и те же часы. Неверная длина, код вне 0–3 или неверное время отклоняют весь кадр без частичного обновления. Передавайте полученные статусы в UI с выбранной периодичностью, отдельно пропуская переходы в зелёный.

Основные исходники: `app/src/main/kotlin/ru/grain/monitor/MainActivity.kt`, `Simulator.kt`, `SensorFilter.kt`. Android-интерфейс нативный; Compose не требуется.

Один зелёный пакет здесь трактуется как немедленное восстановление по запросу. Если реальный датчик способен выдавать ложные значения `1` при забивании, эту политику необходимо проверять по записи реального потока: она может сбрасывать тревогу. Случайная генерация не заменяет калибровку на стенде.
